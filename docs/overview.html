agent_urp 연구 개요

LLM agent trajectory의 dependency-based selective re-execution runtime

skeleton v1 구현 완료 · 78 tests GPU-free 우선 baseline: full rerun / suffix rerun 용어: 논문·공식 문서 기준

완료된 LLM agent trajectory의 입력·tool 결과·memory가 바뀌면 현재 runtime은 full rerun 또는 suffix rerun을 택하고, 그만큼 불필요한 LLM 호출·tool 호출·token 처리 비용이 생긴다. 이 연구는 단계 간 dependency를 기록해 두었다가 영향받은 단계만 invalidation·re-execution 하는 runtime prototype을 만들고, 그 결정을 호출 수가 아니라 prefix cache를 고려한 실제 추론 비용으로 내리는 것을 목표로 한다.

연구 문제

  • 대상: tool-using LLM agent (ReAct 방식의 reasoning + acting). 한 trajectory는 LLM call, tool call, intermediate artifact, memory, context block으로 구성된다.
  • 변경 트리거: (1) 사용자 constraint 수정, (2) tool 실패 또는 tool 결과 변경, (3) memory 교정.
  • baseline: full rerun(전부 재실행), suffix rerun(편집 지점 이후 전부 재실행 — LangGraph time travel의 의미론).
  • 판정: dependency graph에서 dirty propagation을 수행해 각 노드를 REUSE, RERUN, REBUILD로 분류한다(연구활동계획서 용어).
  • 가설: dependency-based partial re-execution은 full/suffix rerun과 같은 결과 품질을 유지하면서 재계산 token과 latency를 줄인다.
  • 성공 기준: stale reuse = 0, task accuracy 저하 최소화, LLM 호출 수·처리 token·실행 시간의 유의미한 감소.

시스템 흐름

재실행 엔진의 모델: durable execution(Temporal)의 deterministic replay를 따른다. orchestration 코드는 편집마다 처음부터 다시 돌리고, 각 step 호출에서 verifying trace(기록된 읽기 버전이 지금과 같은가)와 constructive trace(같은 입력 해시의 과거 출력)를 검증해 함수 실행을 건너뛴다. artifact는 content-addressed라 같은 내용이면 같은 id를 가지므로 하위 step은 자동으로 재사용된다(early cutoff).

비용 모델과 prefix caching

재실행 비용은 prompt token 수가 아니라 KV cache에 없는 token 수에 비례한다. 그래서 "무엇을 재실행하나"뿐 아니라 "prompt를 어떤 순서로 조립하나"가 비용을 정한다.

cost ≈ c_prefill · N_uncached + c_cache · N_cached + c_decode · N_output
  • LLM inference는 prefill(prompt 전체를 한 번에 처리, TTFT를 결정)과 decode(token을 하나씩 생성)로 나뉜다 (PagedAttention, SOSP 2023).
  • Automatic prefix caching(vLLM)은 KV cache를 block 단위로 해시해 같은 prefix를 재사용한다. 해시가 이전 block을 포함하므로 앞쪽 편집은 뒤쪽 전부를 무효화한다. RadixAttention(SGLang)은 radix tree로 같은 일을 한다.
  • Prompt caching(API): Anthropic은 명시적 cache breakpoint와 cache_read_input_tokens/cache_creation_input_tokens를, OpenAI는 자동 캐시와 cached_tokens를 돌려준다. 이 필드로 GPU 없이 prefix cache hit과 비용을 실측한다.
  • 캐시 최소 길이: breakpoint 앞 prefix가 모델별 최소 token(1,024~4,096)보다 짧으면 캐시가 적용되지 않는다. 실험 workload의 안정적 prefix(system prompt, tool schema, memory)는 이보다 길어야 한다.
  • 설계 원칙: 변동성이 낮은 context block을 prompt 앞쪽에 배치해 prefix를 안정화한다. 실제 agent trace에서 캐시를 깨는 세 패턴은 내용 편집, tool 결과 삽입, context 재배열이다 ("Don't Break the Cache", 2026).

평가 프로토콜

Perturbation 시나리오

  1. Constraint 편집 — 여행 계획의 예산 변경
  2. Tool 결과 변경 / 실패 — 리서치 파이프라인의 문서 갱신
  3. Memory 교정 — 사무 작업의 사용자 선호(단위) 수정
  4. No-op 편집 — 같은 뜻의 재표현; 한 번의 재검증 후 early cutoff
  5. Control-flow 분기 — 편집이 다른 tool 선택을 유발; 같은 tool call은 memoization으로 재사용

각 시나리오는 "반드시 재실행될 step" 집합과 "재실행되면 안 되는 control step" 집합을 ground truth로 명시한다.

지표와 동등성 수준

task success, stale reuse rate, 과잉 재실행 수, LLM·tool 호출 수, 입력·출력 token, cached token, 예상 비용, wall-clock 시간, (GPU 단계) TTFT·prefill 시간·GPU 메모리. 비결정성은 temperature 0 + seed, 시나리오당 N≥5회 반복으로 다룬다.

early cutoff의 판정 기준은 실험 변수다: L0 바이트 동일 → L1 정규화 → L2 tool-call canonical → L3 embedding 유사도(GPTCache 방식) → L4 LLM-as-a-judge. 수준을 올릴수록 절감은 늘고 stale reuse 위험은 커진다; 이 곡선을 측정한다.

기존 벤치마크(BFCL v3 multi-turn, ToolSandbox)는 최종 정답만 채점하므로 외부 타당성 앵커로만 쓴다.

주장할 기여 (우선순위 순)

  1. Prefix-cache-aware 재실행 결정 — uncached prefill token을 목적함수로 두고 context block 배치와 재검증 순서를 함께 최적화한다.
  2. 의미적 early cutoff의 정량화 — 동등성 수준별 절감–stale reuse 곡선과 비용 게이트된 LLM-as-a-judge.
  3. Agent 특화 트리거와 동적 그래프 — tool 실패·memory 교정을 1급 트리거로, control-flow 분기를 memoization으로 처리; build systems의 minimality를 정확성 명세로 삼는다.
  4. Perturbation 벤치마크 — 영향 step 집합이 명시된 시나리오로 stale reuse rate를 직접 측정한다.
  5. (선택) 실제 하드웨어 실측 — RTX 4090 + vLLM automatic prefix caching에서 TTFT·prefill 개선.
